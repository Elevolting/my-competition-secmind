# 安全任务平台首次操作指南

本交付包包含三个并列目录：

```text
security-agent-suite/
├─ an/                 统一前端、统一 API、代码审计和应急响应
├─ secmind/            逆向分析服务
└─ security-runtime/   渗透黑板服务和 Dispatcher
```

所有功能只允许用于已授权的本地测试环境。首次启动需要联网安装依赖并自行填写 DeepSeek API Key；交付包不包含发送方的密钥、运行记录、虚拟环境或 `node_modules`。

## 一、环境要求

推荐使用 Windows 10/11、PowerShell 7，并安装：

- Python 3.11 至 3.13；
- `uv`；
- Node.js 20.19 以上或 22.12 以上；
- Docker Desktop；
- Claude Code CLI（当前渗透 Dispatcher 使用它作为 Worker 驱动）。

检查命令：

```powershell
python --version
uv --version
node --version
npm --version
docker --version
docker compose version
claude --version
```

缺少工具时可在管理员 PowerShell 中安装：

```powershell
winget install --id Astral-sh.uv -e
winget install --id OpenJS.NodeJS.LTS -e
winget install --id Docker.DockerDesktop -e
npm install -g @anthropic-ai/claude-code
```

安装后关闭并重新打开 PowerShell，使 `PATH` 生效。

## 二、解压与首次安装

下面假设压缩包解压到 `C:\kaifa\tool\security-agent-suite`。如果放在其他目录，只需把 `$suiteRoot` 改成实际路径。三个模块必须保持并列，不要单独移动某一个目录。

```powershell
$suiteRoot = "C:\kaifa\tool\security-agent-suite"
```

安装统一平台后端依赖：

```powershell
Set-Location "$suiteRoot\an"
uv sync
```

安装前端依赖：

```powershell
Set-Location "$suiteRoot\an\frontend"
npm ci
```

安装逆向服务依赖：

```powershell
Set-Location "$suiteRoot\secmind"
uv sync
```

安装渗透运行时依赖：

```powershell
Set-Location "$suiteRoot\security-runtime\security-runtime"
uv sync
```

## 三、填写模型配置

同一个 DeepSeek API Key 需要分别写入三个模块的本地 `.env`。不要把填写后的 `.env` 发给其他人，也不要提交到 Git。

### 1. 统一平台 `an`

```powershell
Set-Location "$suiteRoot\an"
Copy-Item .env.example .env -ErrorAction Stop
notepad .env
```

至少确认或修改以下内容：

```dotenv
SECURITY_AGENT_API_HOST=127.0.0.1
SECURITY_AGENT_API_PORT=8001
SECURITY_AGENT_DEMO_MODE=false
SECURITY_AGENT_MODEL_BASE_URL=https://api.deepseek.com
SECURITY_AGENT_MODEL_API_KEY=<填写自己的 DeepSeek API Key>
SECURITY_AGENT_REVERSE_BASE_URL=http://127.0.0.1:8002
SECURITY_AGENT_PENETRATION_BASE_URL=http://127.0.0.1:8000
SECURITY_AGENT_PLANNER_MODEL=deepseek-v4-flash
SECURITY_AGENT_WORKER_MODEL=deepseek-v4-flash
SECURITY_AGENT_FALLBACK_MODEL=deepseek-v4-flash
```

模型名称必须是账号实际可调用的模型。如果服务商没有 `deepseek-v4-flash`，应替换为其模型列表中可用的名称。

### 2. 逆向服务 `secmind`

```powershell
Set-Location "$suiteRoot\secmind"
Copy-Item .env.example .env -ErrorAction Stop
notepad .env
```

至少确认或修改以下内容：

```dotenv
SECMIND_DEMO_MODE=false
SECMIND_MODEL_MODE=live
SECMIND_ALLOW_LIVE_MODELS=true
SECMIND_TRUSTED_MODEL_BASE_URLS=https://api.deepseek.com
SECMIND_QWEN_BASE_URL=https://api.deepseek.com
SECMIND_MODEL_BASE_URL_PROVIDER=deepseek
SECMIND_DEEPSEEK_API_KEY=<填写自己的 DeepSeek API Key>
SECMIND_PLANNER_MODEL=deepseek-v4-flash
SECMIND_WORKER_MODEL=deepseek-v4-flash
SECMIND_FALLBACK_MODEL=deepseek-v4-flash
```

不要把网页 Markdown 链接写入 URL。正确值是 `https://api.deepseek.com`，而不是 `[https://api.deepseek.com](https://api.deepseek.com)`。

### 3. 渗透 Dispatcher `security-runtime`

交付包不包含真实 `.env`，首次操作时新建：

```powershell
Set-Location "$suiteRoot\security-runtime"
@'
ANTHROPIC_MODEL=deepseek-v4-pro
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
ANTHROPIC_AUTH_TOKEN=<填写自己的 DeepSeek API Key>
'@ | Set-Content -Encoding utf8 .env
```

这里的 `ANTHROPIC_*` 是 Claude Code CLI 所要求的兼容变量。当前实际调用的是 DeepSeek Anthropic 兼容接口，不是 Anthropic 官方 Claude 模型。`ANTHROPIC_MODEL` 同样必须替换为账号可用的模型。

## 四、打开 Docker Desktop

推荐在其他服务之前启动 Docker Desktop：

```powershell
Start-Process "$env:ProgramFiles\Docker\Docker\Docker Desktop.exe"
```

等待 Docker Desktop 显示 Engine running，然后检查：

```powershell
docker info
docker ps
```

当前推荐方案使用本地 Security Runtime Server 和本地 Claude Code Dispatcher。**不要再执行 `docker compose up` 启动同一套 Security Runtime**，否则会与本地服务争用 `8000` 端口。Docker Desktop 主要供需要容器化安全工具的已授权测试任务使用。

## 五、确认 Claude Code

Claude Code 没有必须单独打开的桌面窗口。确认 CLI 可用即可：

```powershell
claude --version
```

不要提前在另一个终端长期运行交互式 `claude`。启动 Dispatcher 后，它会按任务自动调用 `claude` 子进程。若 `claude` 命令不存在，重新安装：

```powershell
npm install -g @anthropic-ai/claude-code
```

## 六、按顺序启动程序

需要打开五个 PowerShell 窗口，并保持窗口运行。推荐顺序如下。

### 终端 1：渗透黑板服务（8000）

```powershell
$suiteRoot = "C:\kaifa\tool\security-agent-suite"
Set-Location "$suiteRoot\security-runtime"
powershell -ExecutionPolicy Bypass -File .\start-runtime-server.ps1
```

### 终端 2：渗透 Dispatcher（自动调用 Claude Code）

确认终端 1 已启动后执行：

```powershell
$suiteRoot = "C:\kaifa\tool\security-agent-suite"
Set-Location "$suiteRoot\security-runtime"
powershell -ExecutionPolicy Bypass -File .\start-runtime-dispatcher.ps1
```

启动日志中应显示 Worker 健康检查成功。若所有 Worker 都是 unhealthy，请先检查 `.env` 中的模型名称、URL 和 Key。

### 终端 3：逆向服务（8002）

```powershell
$suiteRoot = "C:\kaifa\tool\security-agent-suite"
Set-Location "$suiteRoot\secmind"
powershell -ExecutionPolicy Bypass -File .\启动在线.ps1
```

### 终端 4：统一平台后端（8001）

确认 8000 和 8002 已启动后执行：

```powershell
$suiteRoot = "C:\kaifa\tool\security-agent-suite"
Set-Location "$suiteRoot\an"
powershell -ExecutionPolicy Bypass -File .\启动在线.ps1
```

### 终端 5：统一前端（5173）

```powershell
$suiteRoot = "C:\kaifa\tool\security-agent-suite"
Set-Location "$suiteRoot\an\frontend"
powershell -ExecutionPolicy Bypass -File .\启动前端.ps1
```

## 七、打开页面与健康检查

浏览器打开：

```text
http://127.0.0.1:5173
```

PowerShell 健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/projects
Invoke-RestMethod http://127.0.0.1:8002/health/live
Invoke-RestMethod http://127.0.0.1:8001/health
Invoke-RestMethod http://127.0.0.1:8001/api/v1/modules
```

查看端口占用：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -in 5173,8000,8001,8002 |
  Sort-Object LocalPort |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

正常情况下应存在：

| 端口 | 模块 |
| ---: | --- |
| 5173 | 统一前端 |
| 8000 | 渗透黑板服务 |
| 8001 | 统一平台后端 |
| 8002 | 逆向服务 |

## 八、常见问题

### 端口已被占用（WinError 10048）

先找出进程，不要重复启动服务：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -in 5173,8000,8001,8002 |
  Select-Object LocalPort,OwningProcess
```

只在确认是需要关闭的旧实例后，才执行：

```powershell
Stop-Process -Id <OwningProcess 中的 PID>
```

### 前端显示“断开连接”

确认统一后端为 `8001`，并使用 `an\frontend\启动前端.ps1` 启动。该脚本会把前端代理指向 `http://127.0.0.1:8001`。

### 渗透任务不推进

同时检查：

1. `8000` 的 Security Runtime Server 是否可访问；
2. Dispatcher 窗口是否持续运行；
3. `claude --version` 是否成功；
4. `security-runtime\.env` 的三个变量是否填写；
5. Docker Desktop 是否已经启动；
6. Dispatcher 日志是否出现 Worker unhealthy、401、404 或模型不存在。

### 逆向服务启动失败

确认 `SECMIND_QWEN_BASE_URL` 是纯 URL，且 `8002` 没有被旧进程占用。访问根路径出现 `404` 不代表服务失败，应检查 `/health/live`。

## 九、关闭程序

在五个运行终端中分别按 `Ctrl+C`。关闭服务后可保留 Docker Desktop；如果不再需要容器环境，再从 Docker Desktop 菜单退出。不要直接删除运行中的数据库或任务目录。
