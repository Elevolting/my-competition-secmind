# 黑板工具调用与资产引用图加固

本次实现参考 TheHive 的 case/task/evidence 审计线、OpenCTI 的实体关系与来源、Velociraptor 的可复核采集，以及 LangGraph 的可恢复工作流原则。只读取公开 GitHub README 作为设计参考，没有对第三方目标执行扫描或调用。

## 已落地

- 资产引用图读取同一任务的黑板 MCP 持久化回执。成功调用的网络目标会显示为 `invoked`，并保留调用 ID、完成时间和来源；工具回执显式提供 `structuredContent.coverage` 时，才标为 `discovered` 并计入有效覆盖观测。
- 调用目标通过统一授权范围解析。除常见 `url`/`target` 外，Burp HTTP/1 请求的 `targetHostname`、`targetPort`、`usesHttps`、请求行和 Host 头会一起校验，防止连接目标与请求目标不一致。
- 路径范围在解码和规范化后匹配，拒绝目录穿越、编码绕过、越界主机、端口或协议。
- 资产图节点区分授权范围、输入材料、已调用目标和工具发现；页面统计不再把调用次数冒充扫描覆盖率。
- 黑板仍是工具调用的必经门禁：项目身份、意图租约、Worker、预算、工具版本、回执和任务工作区都要通过校验。已停止或过期租约收到 409 属于拒绝调用，不能通过放宽鉴权处理。

## 验证

- 后端黑板、资产图、MCP 范围和经验库组合回归通过。
- 前端 26 项测试通过，生产构建通过。
- Ruff F/I 检查通过。
- 重启 8001 后，真实资产图 API 对历史 MCP 回执返回 8 次授权调用、4 个已调用资产节点和 3 条关系，并保留 provenance。
- 8001、8002、5173 服务保持本机监听；8000 黑板服务可用。当前没有启动 Dispatcher，避免旧 Worker 在停止项目上反复请求工具；启动新渗透任务时应使用当前 `dispatch.local.yaml` 和有效模型配置。
