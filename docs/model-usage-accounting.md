# 模型用量统计

本机套件的“模型配置与用量”页面现汇总三个来源：主任务 Agent、SecMind 分析引擎和 Security Runtime Worker。

- 主 Agent：按原有 Provider 请求回执统计。
- SecMind：从本机 `secmind/data/secmind.db` 的调用审计记录读取真实 Provider 用量；旧审计记录仅在存在明确标注 Provider 用量的原始响应回执时补齐。内部保守预算估算不计入真实 Token。可用 `SECURITY_AGENT_SECMIND_USAGE_DATABASE` 指定其他本机数据库。
- Worker：优先使用 Claude CLI 和 Pi 的 JSON 结果回执；执行、推理和收尾阶段分别记录。启用 `shared_model_config` 后，Dispatcher 自动把记录保存在共享配置旁的 `worker-usage.db`，因此本机启动脚本无需额外参数。输入 Token 包含普通输入、缓存读取和缓存创建；缓存读取另有明细。旧回执缺少用量时，可从本机保留的 Pi 或 Claude Code 会话恢复助手响应级供应商数字，但只限项目目录、Runtime 项目时间窗与有效用量同时匹配且没有被已有 Token 回执覆盖的响应；重复内容块只计算一次。

Worker 的“调用次数”按 CLI 执行计数，一次执行可能包含多轮 Provider 响应；已知用量以 CLI 汇总回执为准，只有该执行回执为空且会话记录能安全关联时才补响应级用量，不会把补录响应算作额外执行。失败、取消、超时或异常终止而缺少回执时，执行次数保留，用量标为未知。没有匹配的项目时间窗和会话回执时不估算历史消耗。

平台以只读方式读取两边数据库，将白名单用量字段写入自己的账本。来源、原始调用 ID、模型、项目/任务、阶段和原始时间会保留；密钥、提示词及模型输出不会写入用量账本。稳定事件 ID 保证刷新和重启后重复同步不会重复计入，小时/日/月图表使用调用原始时间。

页面每 15 秒刷新；打开用量页面或有关联外部任务的任务详情时同步新记录。每次最多导入每来源 2000 条，超过时显示“正在补齐历史”。来源故障时保留已导入记录并提示统计不完整。任务详情包含关联外部任务消耗，任务列表的快速预算摘要仍仅代表平台 Agent。

接口 `/api/v1/model-usage` 新增 `usage_by_source` 和 `source_series`；原有总量、模型明细及时间序列都包含已同步的外部用量。

这是本机套件的调用统计，不是供应商账户账单，也不包含其他机器或其他应用的调用。额度仍为 `warning_only`，只提醒，不自动阻止 Worker 或主 Agent 继续调用模型。SecMind 仍使用其独立模型配置；渗透 Worker 继续继承平台共享模型配置。
