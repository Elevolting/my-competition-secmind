# 任务失败恢复与手动重试

工作台现在会为部分完成、失败任务显示停止原因和“重试任务”入口。重试沿用原任务材料、目标、授权范围和审批策略，以新运行编号重新规划、执行，保留原任务记录和证据，并提供返回来源任务的链接。旧任务的超时和工具错误也可直接显示，无需修改历史数据。

重试窗口支持 1–120 分钟的运行时限；耗尽时间预算的任务默认建议原时限的两倍（最多 120 分钟）。新任务使用当前配置的步骤、工具调用和模型调用预算。时间加长不代表其他预算被取消。

接口为 `POST /api/v1/runs/{run_id}/retry`，请求包含 `request_id` 和可选的 `max_runtime_seconds`。相同请求编号重复提交会返回同一新任务；同一来源已有重试任务运行或待审批时也返回该任务。该关联持久化在运行快照中。运行中、已完成、已拒绝的任务不可重试，外部任务尚未确认结束时需先同步外部状态。

恢复行为：

- 临时超时、连接重置等错误只对允许安全重复的调用执行有限重试；本地 TscanPlus HTTP 工具只允许无请求体的 GET/HEAD 自动重试，POST 不自动重放，仍保留原风险和审批检查。
- 协议错误不会原样自动重试。重试任务的规划上下文包含上次错误，并要求按实际协议选择工具。
- 普通 MCP 调用失败后跳过依赖该步骤的后续步骤，继续独立分支；跳过与失败会进入账本和报告，完成步数不包含这些步骤，最终结果保留为部分完成。
- 远程任务失败、审批拒绝、证据验证失败和预算耗尽仍停止执行，不通过普通工具重试创建重复远程任务。

验证：后端全部 175 项测试、前端 26 项测试通过；Vite 构建通过。浏览器验证覆盖历史停止原因、预算建议、提交参数、网络错误后复用请求编号、新任务跳转、来源链接以及桌面和手机布局。浏览器提交使用拦截响应，没有重新执行用户的四个靶场任务。
