# 独立复核操作与数据边界

## 使用方式

在统一平台的任务结果页打开某项发现或报告结论的「独立复核」。应急控制台的已完成动作回执可点「复核研判」，系统会校验回执并建立只读来源报告，然后进入同一复核入口。可补充说明、上传修复版本或其他新材料，并单独设置时限、工具和模型调用预算。创建后从历史记录进入子任务，查看执行状态和本次证据。完成后选择结论、对应的本次证据及摘要，再保存。原任务报告是历史快照；报告 API 在读取时附加已登记的复核历史，并同时列出原证据和本次证据编号。

复核沿用原任务目标和授权范围。原输入由系统核验哈希后暂存给子任务；新材料须先通过上传入口提交。原任务的单次受限 POST 授权不会自动继承。若目标不可达、登录态失效、验证路径未覆盖或材料不足，登记「无法确认」。

| 来源模块 | 有效结论 | 必需的本次证据角色 |
|---|---|---|
| 渗透 | 仍可复现；已修复 | 漏洞证明；或原触发检查、正常对照和可比前置条件 |
| 代码审计 | 仍可复现；已修复 | 验证结果；或原路径覆盖和验证结果 |
| 逆向 | 支持原结论；推翻原结论 | 重新取证 |
| 日志分析／应急研判 | 支持原结论；推翻原结论 | 重新取证、材料与时间范围 |

有效结论的证据编号必须属于本次子任务报告，并能追溯到本次成功执行的回执；带文件的证据还要通过哈希校验。服务端校验来源和角色，结论的实际含义仍需复核人阅读材料判断。部分完成的子任务只能登记「无法确认」。已保存的结论不能改写；需要新判断时发起下一次复核。

## 恢复与限制

同一来源对象同时只允许一个活动复核。相同请求编号会返回原记录；不同请求遇到活动复核也会返回该记录，并使用原请求保存的预算与材料接续尚未提交的子任务。提交阶段由数据库原子认领；进程在认领后中断且子任务尚未落库时，认领五分钟后可由后续请求或服务启动后的后台重查恢复。已落库的子任务由统一任务恢复机制继续执行。取消及失败保留已有记录与证据。

应急控制台的动作回执映射为稳定的统一来源任务，原动作 ID、材料哈希和执行时间一并保存；相同动作重复打开不会生成第二份来源。采集快照会核对原文件哈希，处置动作只导入执行回执，复核不会重放隔离、恢复或防火墙命令。处置回执只能说明当时的执行记录；要判断当前主机状态，须上传或采集本次材料。尚未形成动作回执的实时监控事件和待审批动作不能发起复核。界面显示的报告复核历史来自读取时投影，不改变原报告的数据库内容。

## 本地验证

在 `an` 目录运行 `uv run pytest tests/test_retests.py tests/test_incident_review.py tests/test_traces.py tests/test_traffic_evidence.py -q`、`python frontend/tests/retest-browser.py` 和 `python frontend/tests/incident-review-browser.py`；在 `an/frontend` 运行 `npm test`、`npm run build`。浏览器夹具使用隔离的 API mock，不会向正式后端写入复核记录。
