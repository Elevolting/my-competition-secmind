# 技能统计：数据口径、部署与恢复

## 页面与接口

工作台侧栏「系统能力 → 技能使用统计」，路径 `/skills`。可按技能编号、工作台任务编号、角色和事件类型查询；事件详情保留账本事件编号、序号、时间、载荷及哈希，已映射的任务可跳转任务页面和审计页面。

工作台与独立分析引擎均提供：

- `GET /api/v1/skills/usage?run_id=...&skill_id=...&role=...&event_type=...&limit=50&offset=0`
- `GET /api/v1/skills/usage/events/{event_id}`

`limit` 为 1–200，`offset` 非负。角色／技能的未知值为 `unknown`。事件类型只筛选事件列表，顶部总数和技能聚合仍按完整调用生命周期计算。工作台 `run_id` 是本地任务编号，引擎 `run_id` 是远端任务编号。

## 指标含义

| 指标／事件 | 计数边界 |
|---|---|
| 加载成功／`skill.loaded` | 注册表真实加载、包核验完成后记录；用途包括上下文加载、规划核验和执行前核验 |
| 加载失败／`skill.load_failed` | 加载抛出异常后记录错误类型；不保存技能正文、异常正文或凭据 |
| 实际调用／`tool.invoked` | 调用已领取，策略及适用的执行契约、dispatch permit 校验通过后，抵达 `tool.invoke()` 前的执行边界 |
| 调用成功 | 同一次实际调用的结果回执为 `success` |
| 调用失败 | 同一次实际调用产生异常或返回其他结果状态 |
| 尚无结果 | 已有调用边界事件，尚无终态回执；可能仍在运行，也可能在崩溃后结果未知 |

`tool.invoked` 证明抵达调用边界；写入此事件后、工具实际开始前仍存在崩溃窗口，因此不能单凭它证明外部操作已经生效。实际成功或失败以对应结果回执为准。

一次真实重试采用 ExecutionStore／UnitOfWork 返回的独立 invocation attempt，计为新的调用；缓存读取、已有调用进行中、授权拒绝、恢复待处理均不增加调用计数。逻辑调用重放和 outbox 重复投影保持幂等。

技能归因仅使用已核验 `AgentWorkContract` 的技能绑定和角色。合同里多个技能属于候选关联，不能证明具体哪个技能产生了结果。同一调用关联两个技能时，各技能的关联调用分别加一，任务调用总数只加一。没有可核验合同或绑定时保留未知归属，不从选中技能或日志文字猜测。加载次数、调用成功率不等于漏洞检出率。

## 部署与服务边界

引擎统计复用原事件账本与 fenced outbox，无新增独立业务表。工作台是只读查询桥接，使用现有 `reverse_base_url` 和 `secmind_operator_token`；凭据仅放在服务间 Authorization 头。

工作台通过 `external_execution.remote_run_id` 关联任务。没有远端任务引用的任务返回明确的不可用原因。首版覆盖独立分析引擎的真实技能加载和工具调用；不声称覆盖全部 Runtime／Pi Worker 技能使用。全局查询展示引擎账本全部可查询事件，无法映射到工作台的事件保留远端编号。

历史任务没有新增事件时不补推加载或执行事实；旧 `tool.started` 不是实际调用来源。旧结果没有稳定 usage identity 时不参与统计。引擎的连接、认证、无效 JSON 或响应结构错误在工作台返回受控错误，详情不存在返回 404。

## 恢复与故障排查

持久执行事件先进入 outbox，再由既有 OutboxProjector 投影到账本，页面可能短暂滞后。统计未更新时先查投影服务及队列，再刷新页面；重复投影不重复计数。服务恢复后读取同一数据库即可继续查询；禁止为了补统计重放工具操作。

失效租约不能产生新调用或加载事件。初始化尚未领取执行租约时的上下文加载沿用既有 coordinator 接纳阶段的事件契约。账本沿用既有脱敏和哈希链；usage identity 使用稳定 UUID，避免裸哈希被脱敏后将不同操作合并。

查询目前流式扫描符合任务条件的使用事件，只保留当前页事件，但聚合仍维护加载／调用身份集合。耗时为 O(N)，内存与不同操作身份数相关；工作台任务映射也需扫描任务状态。大型账本优先按任务筛选，后续再根据量级增加可重建的统计投影和映射索引。

## 本地验收（2026-10-15）

- 引擎相关回归 79 项通过；随后新增真实执行契约整合场景 2 项通过，验证多技能候选、实际 dispatch permit、执行身份、缓存和合同拒绝。原专项 9 项已包含于 79 项。
- 工作台桥接 9 项通过，含认证转发、任务映射、缺少引用、无效参数、HTTP／连接故障、无效 JSON 和异常响应结构。
- 前端单元测试 55 项通过，生产构建成功。浏览器 API 夹具通过分页、技能／任务／角色筛选、迟到响应、列表及详情重试、任务与审计跳转、详情关闭和窄屏布局。
- 新增模块 Ruff 检查通过；相关账本恢复、重试、重复投影和迟到租约测试使用隔离临时数据库。验收未调用付费模型或真实目标，未重启现有服务。

设计参考 ARTEX `db/skill_usage.go`、`server/skill_usage.go` 和 `agent/tools.go`。ARTEX 的注册表命中指标不同于 SecMind 的真实加载成功和实际工具调用；实现为 Python 账本上的原创接入，未直接复制 ARTEX 源码。根目录许可为 AGPL-3.0，若后续复制代码需按具体文件确认许可并记录来源版本、修改和声明。
